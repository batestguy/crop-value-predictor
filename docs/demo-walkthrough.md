# Demo walkthrough

The 64-second recording at [`docs/media/demo-walkthrough.mp4`](./media/demo-walkthrough.mp4)
shows the whole calculator workflow in one take. This page documents what each
stage demonstrates, how the recording is produced, and what it does not cover.

## What it shows

| # | On-screen caption | What it demonstrates |
|---|---|---|
| 1 | Start with how much land you farm — every figure scales from it. | A single farm area drives every calculation. |
| 2 | Pick two or more crops; the shortlist carries through every step. | Multi-crop comparison; no ranking with fewer than two crops. |
| 3 | Not on the list? Add the crop and how it is sold. | Custom crops (`Soybean` + `dry grain`) join the same shortlist. |
| 4 | Ask the research assistant for starting values. | The optional web lookup, requested for one crop and one state. |
| 5 | Check the price, range and sources before you use anything. | The estimate, range, bag equivalents, warning and evidence links are shown before anything is applied. |
| 6 | Use it as a starting point — then type your own price. | The returned ₦1,250/kg is replaced with the farmer's ₦1,180/kg. The figure is never adopted silently. |
| 7 | The other crops go in by hand: yield, price, eight costs. | Complete manual entry, including the eight cost categories. |
| 8 | Nothing is ranked until every selected crop is complete. | The ranking is withheld while any selected crop is incomplete. |
| 9 | Add a price range to see the spread — not a forecast. | Optional low/high prices produce an interval, labelled as a scenario range. |
| 10 | Change the bag size and every price shows in your bags. | NGN/kg stays authoritative while bag equivalents update. |
| 11 | Print the same figures, with the same basis and wording. | The printable report is generated from the same result object as the screen. |
| 12 | Reload with the network off. The scenario is still there. | Local persistence and the offline app shell after a hard reload. |

## How it is produced

The recording is generated by [`scripts/demo-capture.mjs`](../scripts/demo-capture.mjs).
It is documentation tooling: the app never imports it.

```powershell
npm.cmd run build
npm.cmd run preview -- --port 4180 --strictPort

# stills only (2x device pixels, no captions)
node scripts/demo-capture.mjs --shots

# video only (1x, captions burned in)
node scripts/demo-capture.mjs --video
```

The script drives a real Chromium session against the production build. Each
stage is a caption plus at least one visible action, padded to a minimum
on-screen duration, so no frame is filler and no caption flashes past.

### The research response is stubbed

The Quick Research request is intercepted with `page.route()` and answered from
the `RESEARCH_RESPONSE` constant in the script. This keeps the take
deterministic, spends no Tavily credits, and needs no credentials.

The app itself is unmodified — only the numbers returned by that one request are
fixed. The stub is disclosed on screen (small badge, bottom right) and in the
README next to the video link. The figures shown (₦1,250/kg, ₦1,100–₦1,400,
2.4 t/ha) are illustrative, not a market observation.

### Encoding

The raw WebM is re-encoded to H.264/AAC with the local soundtrack:

```powershell
ffmpeg -y -i docs/media/demo-walkthrough.webm -i Instance_2face_Naijapals.mp3 `
  -map 0:v:0 -map 1:a:0 -c:v libx264 -preset medium -crf 26 -pix_fmt yuv420p `
  -c:a aac -b:a 96k -ar 44100 `
  -af "volume=-7dB,afade=t=in:st=0:d=1.2,afade=t=out:st=61:d=3" `
  -shortest -movflags +faststart docs/media/demo-walkthrough.mp4
```

The source audio is deliberately **not committed** (`Instance_2face_Naijapals.mp3`
is in `.gitignore`) and the intermediate `.webm` is ignored too; only the encoded
MP4 is tracked.

## Screenshots

Stills come from the same script and the same build, so they cannot drift from
the video. `--shots` runs at twice the device pixel ratio for sharp text.

| File | What it shows | Capture |
|---|---|---|
| `seasonmargin-overview.png` | Home screen: the promise, the field note, the first step | 1280 px viewport |
| `decision-view.png` | Four crops ranked, price basis and units strip | 1280 px viewport |
| `research-output.png` | The research panel at full width: estimate, range, warning, starting values, sources, apply button | 620 px viewport, `.editor-card` element |
| `print-report.png` | The printable report for all four crops | `.print-report` element in print media |
| `mobile.png` | The same calculator at 390 px | phone viewport |

The research still is captured at 620 px on purpose: at desktop width the
research panel is a 220 px column with empty space beside it, which reads poorly
in a README. At 620 px the same panel spans the card.

## Known gaps

- The demo covers the main path, not every state. The corrupt-draft notice,
  blocked-local-storage notice, and the modeled-estimate banner are not shown.
- The researched crop is a custom crop, so it has no photograph. Built-in crops
  do.
- The recording is a local production build, not the deployed site.

## Maintenance

Re-run `--shots` and `--video` after any change to calculator copy, layout, or
the research panel, then check a contact sheet for dead air:

```powershell
ffmpeg -y -i docs/media/demo-walkthrough.webm -vf "fps=1/5,scale=400:-1,tile=4x3" -frames:v 1 sheet.png
```

If a caption no longer matches the UI, update it in `scripts/demo-capture.mjs`
rather than editing the video.
